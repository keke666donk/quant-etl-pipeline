# A股行情自动化 ETL 数据管道
基于 Python、Pandas 与 SQLite 构建的本地化行情数据管道，旨在为量化分析提供高可用、防重复的干净数据源。
## 技术栈
- **语言**：Python
- **数据处理**：Pandas, NumPy
- **数据库**：SQLite3
- **数据源**：AKShare (腾讯/东财接口)
## 核心功能与工程实践
1. **数据源选型与多源容灾**：
   最初计划使用 Tushare，但调研发现其前复权等核心接口需要付费积分，故果断转向完全免费且支持前复权的 AKShare。在初期使用东方财富接口时，遭遇了严重的 IP 封禁（`Connection aborted`）。排查期间，曾尝试切换至手机热点网络以绕过限制，但依然被目标网站的风控机制拦截。最终，通过分析报错日志，将底层数据源平滑切换至更稳定的腾讯财经接口，并在循环中引入了 `time.sleep(random.uniform(2, 4))` 随机休眠机制，不仅彻底解决了封禁问题，还保证了管道的长期高可用性。
2. **数据清洗与格式对齐 (Transform)**：
   对源数据进行了严格的清洗逻辑。首先，过滤掉成交量为 0 的停牌脏数据，防止干扰后续的计算；其次，处理复杂的时间格式，将 datetime 对象统一转换为标准的 8 位纯数字字符串（如 `20260901`）；最后，利用代码切片动态生成交易所后缀（如将 `sz000001` 转换为 `000001.SZ`），完美对齐了标准量化数据库的表结构。
3. **增量更新机制 (防重复)**：
   彻底摒弃了全量覆盖的低效做法。每次运行前，通过 SQL 语句 `SELECT MAX(trade_date)` 动态查询数据库中该股票的最新日期，并结合 `datetime.timedelta` 计算增量区间。实现了“有则更新，无则跳过”的逻辑，从根源上杜绝了 `append` 写入导致的冗余数据问题。
4. **安全批量入库 (Load)**：
   采用 Pandas 的 `to_sql` 方法进行批量入库，大幅提升了海量数据的写入效率。同时结合 `try-except` 容错机制，确保单只股票拉取失败不会导致整个管道崩溃，增强了程序的鲁棒性。
   ## 数据结构 (Table Schema)
数据持久化保存在 SQLite 数据库文件 `quant.db` 中，核心表名为 `daily_price`。表结构设计如下：
| 字段名 (Column) | 数据类型 (Type) | 说明 (Description) |
| :--- | :--- | :--- |
| `ts_code` | TEXT | 股票代码（带交易所后缀，如 000001.SZ） |
| `trade_date` | TEXT | 交易日期（格式为 YYYYMMDD，如 20260901） |
| `open` | REAL | 开盘价 |
| `high` | REAL | 最高价 |
| `low` | REAL | 最低价 |
| `close` | REAL | 收盘价（前复权） |
| `vol` | REAL | 成交量 |
*(注：使用了 SQLite3 数据库，支持无缝迁移至 PostgreSQL 等生产级数据库。)*
